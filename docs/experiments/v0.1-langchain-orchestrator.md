# v0.1 时期 LangChain orchestrator 尝试 - 复盘

> 写于 2025-09 整理老仓库时,回顾 2024-Q4 在 v0.1 上试过的 LangChain 集成。
> 用 "复盘" 的形式留下来,免得后人重蹈覆辙。

## 当时想解决什么

v0.1 的代码生成是单步:**接收数据库连接 → 一把生成所有 Java 文件**。LLM 在中间几乎没有发挥空间,工具调用是黑盒。

当时的判断:**"LLM 工作流应该是 chain"**,所以引入 LangChain 试试。

## 实际做了什么 (2024-10 ~ 2024-11)

引入依赖:
```
langchain==0.0.350
langchain-anthropic==0.0.5
```

包装了 3 个 LangChain Tool:
1. `connect_db_tool` - 测试数据库连接,返回 schema
2. `generate_entity_tool` - 给定 table_name 渲染 Entity
3. `generate_full_stack_tool` - 渲染整套 (Entity/DAO/Service/Controller/Mapper)

然后用 `AgentExecutor` + Claude (Sonnet 3.5) 跑:

```python
agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True, max_iterations=10)
result = executor.invoke({"input": "从 myapp 数据库的 sys_user 表生成代码"})
```

## 失败的几个具体原因

### 1. 抽象层堆叠,失控

LangChain 自己有 3 层:
- `AgentExecutor`(调度)
- `BaseTool` 包装我们的函数
- `ChatPromptTemplate` + `MessagesPlaceholder` 拼 prompt

每层都有自己的 callback / state / memory。调试一次"为什么 Claude 没调 generate_entity_tool"需要往三层都打 print。

### 2. 本质不是 chain

我以为多个工具调用 = chain。实际上**生成代码就是 1 次工具调用**:LLM 决定"调 generate_full_stack_tool",参数填好,完事。这不需要 ReAct loop,不需要 reasoning trace,不需要 memory。

LangChain 的价值在多步工作流(查信息 → 推理 → 决定下一步 → 查更多),而我们的场景是单步。

### 3. 调用 Claude API 的部分被 LangChain 包装得很深

想看实际打给 Anthropic API 的 messages 长什么样,需要从 `AgentExecutor.invoke` → `runnable.invoke` → `LLMChain._call` → `llm.invoke` → `_create_chat_result` 一路 print。

对比直接用 `anthropic.Anthropic().messages.create(...)` — 一行代码就清楚了。

### 4. Token 浪费

每轮 ReAct trace(`Thought:` → `Action:` → `Observation:`)都会进上下文。对一个本质 1-step 的任务,这是几倍的 input token 浪费。

实测一次完整生成:LangChain 路径 6800 input tokens vs 直接 API 路径 2400 tokens。

## 最终决策

2024-11 中,移除 LangChain 全部依赖,把 3 个 tool 函数改回普通 Python function,直接 import 调用。

LLM 这一侧改成 **Anthropic SDK 直调**,中间不要 framework。

## 学到的(写在这里给以后看)

1. **Framework abstraction is overkill 是真的**:LangChain 解决的是"多步 ReAct loop"问题,我们没有这个问题。
2. **找你需要的最小抽象**:1 个函数 + 1 次 API 调用 = 不需要 framework。
3. **debugability 比抽象更重要**:能 1 行代码看到 API 真实 payload,胜过 10 层装配。
4. **LangChain 不是错,场景错**:它适合 RAG / 多步工具调用,不适合 codegen 这种"一次合成"任务。

## 这个复盘的现实意义

2024-11 这个决定的副作用是 v0.1 没有"agent loop"。但 2025-09 现在回看,Anthropic 正在推 Claude Agent SDK(下周发布),它就是"轻 SDK + 模型自带能力"的路线。

LangChain 替换为直调,是**意外做对了**。
