# DBJavaGenix MCP服务启动方式

DBJavaGenix提供了三种核心启动方式，适用于不同的使用场景和环境。

## 1. 直接Python启动（推荐用于开发环境）

### 启动命令
```bash
# 在项目根目录下执行
python -m dbjavagenix.cli server
```

### 标准JSON配置
```json
{
  "mcpServers": {
    "dbjavagenix": {
      "command": "python",
      "args": ["-m", "dbjavagenix.cli", "server"]
    }
  }
}
```

### 说明
- 适用于开发和调试环境
- 需要确保在项目根目录执行
- 需要正确设置PYTHONPATH环境变量

### 环境要求
- Python 3.9+
- 已安装项目依赖（通过 `pip install -e .` 或 `uv sync`）

### 使用示例
```bash
# 进入项目目录
cd /path/to/DBJavaGenix

# 设置环境变量（Linux/Mac）
export PYTHONPATH=src

# 启动服务
python -m dbjavagenix.cli server
```

```cmd
# Windows CMD
cd /d C:\path\to\DBJavaGenix
set PYTHONPATH=src
python -m dbjavagenix.cli server
```

```powershell
# Windows PowerShell
cd C:\path\to\DBJavaGenix
$env:PYTHONPATH = "src"
python -m dbjavagenix.cli server
```

## 2. Node.js包装器启动（推荐用于Cherry Studio等MCP客户端）

### 启动命令
```bash
# 在项目根目录下执行
node index.js
```

### 标准JSON配置
```json
{
  "mcpServers": {
    "dbjavagenix": {
      "command": "node",
      "args": ["index.js"]
    }
  }
}
```

### 说明
- 适用于MCP客户端集成（如Cherry Studio）
- 自动处理环境变量设置
- 提供更好的错误处理和进程管理
- 跨平台兼容性更好

### 特点
- 自动设置PYTHONPATH
- 项目结构验证
- 优雅关闭处理
- 详细的启动日志

### 使用示例
```bash
# 进入项目目录
cd /path/to/DBJavaGenix

# 启动服务
node index.js
```

## 3. 零配置启动（推荐用于生产环境）

### 启动命令
```bash
# 安装后直接使用
dbjavagenix-server
```

### 标准JSON配置
```json
{
  "mcpServers": {
    "dbjavagenix": {
      "command": "dbjavagenix-server",
      "args": []
    }
  }
}
```

### 说明
- 适用于生产环境部署
- 需要先安装项目（`pip install .` 或 `pip install -e .`）
- 无需设置环境变量
- 系统级命令，可在任意目录执行

### 安装方式
```bash
# 开发安装（推荐）
pip install -e .

# 或者标准安装
pip install .
```

### 使用示例
```bash
# 安装后可在任意位置执行
dbjavagenix-server

# 带配置文件启动
dbjavagenix-server --config /path/to/config.yaml
```

## 启动方式选择指南

| 使用场景 | 推荐启动方式 | 说明 |
|---------|-------------|------|
| 开发调试 | 直接Python启动 | 便于调试和查看详细输出 |
| IDE集成 | Node.js包装器 | Cherry Studio等MCP客户端的最佳选择 |
| 生产部署 | 零配置启动 | 简单易用，系统级命令 |

## 配置选项

所有启动方式都支持以下配置选项：

### 零配置模式
- 无需配置文件即可启动
- 所有配置通过LLM动态提供
- 适用于智能代码生成场景

### 配置文件模式
```bash
# 使用配置文件启动
dbjavagenix-server --config config.yaml
python -m dbjavagenix.cli server --config config.yaml
node index.js  # 配置文件通过环境变量或MCP协议提供
```

## 故障排除

### 常见问题

1. **ModuleNotFoundError: No module named 'dbjavagenix'**
   - 确保在项目根目录执行
   - 检查PYTHONPATH是否正确设置
   - 使用Node.js包装器方式启动

2. **Python not found**
   - 确保Python已安装并添加到PATH
   - 使用Node.js包装器会提供更清晰的错误信息

3. **权限问题**
   - 确保对项目目录有读写权限
   - 在Linux/Mac上可能需要执行权限：`chmod +x index.js`

### 日志查看
- 所有启动方式都会输出详细的启动日志
- 错误信息会明确指出问题原因
- Node.js包装器提供额外的诊断信息

## 最佳实践

1. **开发环境**：使用直接Python启动方式，便于调试
2. **集成测试**：使用Node.js包装器，确保环境一致性
3. **生产部署**：使用零配置启动，简化部署流程
4. **多环境支持**：Node.js包装器提供最好的跨平台兼容性
