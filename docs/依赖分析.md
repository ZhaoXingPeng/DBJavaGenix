javax.annotation.Resource 和 javax.validation.Valid 是 Java 开发中常用的注解，前者用于资源注入（如依赖注入），后者用于 Bean 验证的级联验证。这些注解最初属于 Java EE（Enterprise Edition）规范的一部分，但随着 Java 生态的演进，它们所在的包已被视为过时。下面将详细阐述其来源、依赖、过时状态、历史背景、迁移指南以及相关工具和最佳实践，以提供全面的参考。

首先，从来源来看，javax.annotation.Resource 来自 Common Annotations for the Java Platform API（JSR 250），这是一个标准注解库，用于声明资源引用，如 EJB、JMS 等。 其 Maven 依赖为 `javax.annotation:javax.annotation-api`，最新版本为 1.3.2（发布于 2018 年 2 月），该 artifact 被 7712 个项目使用，在 Maven 仓库中排名第 80 位。 同样，javax.validation.Valid 来自 Bean Validation API（JSR 380），用于标记字段或方法以进行验证级联。 其 Maven 依赖为 `javax.validation:validation-api`，版本 2.0.1.Final（发布于 2017 年 12 月），被 7354 个项目使用，在 Maven 仓库中排名第 84 位。

这些包的过时状态源于 Java EE 到 Jakarta EE 的转型。2017 年，Oracle 将 Java EE 捐赠给 Eclipse 基金会，后者于 2019 年将其更名为 Jakarta EE，以避免商标问题。 这导致所有 `javax.*` 包被重命名到 `jakarta.*`，包括注解和验证 API。 到 2025 年，`javax` 版本已被明确标记为遗留代码，不再积极维护。 例如，在 GitHub 上有报告显示，Dagger 等框架已移除对 `javax.annotation` 的依赖，转而使用 Jakarta。 虽然注解类本身未添加 `@Deprecated` 注解（以避免破坏现有代码），但 Maven 仓库明确指出这些 artifact 已迁移到 Jakarta 对应物。

在 Jakarta EE 中，javax.annotation.Resource 对应 jakarta.annotation.Resource，功能完全相同，仅包名变化。 Jakarta 版本的 artifact 为 `jakarta.annotation:jakarta.annotation-api`，最新版本 3.0.0（发布于 2024 年 4 月）。 同样，javax.validation.Valid 对应 jakarta.validation.Valid，artifact 为 `jakarta.validation:jakarta.validation-api`，最新版本 3.1.1（截至 2025 年 2 月）。 Jakarta 版本支持更新的规范，如 Bean Validation 3.0，提供增强的验证功能，如对记录类的支持。

迁移过程相对简单：首先，更新导入语句，例如将 `import javax.annotation.Resource;` 改为 `import jakarta.annotation.Resource;`。 然后，替换 Maven 依赖，并使用工具如 OpenRewrite 的迁移配方自动化包名替换。 对于 Spring Boot 用户，在版本 3+ 中，默认使用 Jakarta，因此需确保所有依赖兼容。 如果项目使用 Java 11+，`javax` 包可能导致 NoClassDefFoundError，因为这些模块已从 JDK 中移除。
